In production

Onix, a WhatsApp sales agent

Small shops in Colombia sell a lot through WhatsApp. Onix answers their customers: it finds products in the catalog, recognizes a product from a photo the customer sends, takes the order and the delivery address, and guides the payment. When a customer sends a payment receipt, the owner gets a button to approve it. Each shop sets up its own catalog and rules from a web panel.

The first versions let the model write the reply and then tried to fix it with checks. At one point there were forty of them, and it still went wrong. So I turned it around. Now a LangGraph graph decides which tools the model can use at each step of the sale, and only those tools can read prices or create an order. If a reply mentions a price that no tool returned, it gets rewritten before it is sent.

Each step uses a different model: DeepSeek while the customer browses, Gemini at checkout, Claude for photos, with a fallback if one is down. Photos are matched to products with embeddings in pgvector. An order can't be created twice, and each shop's data is kept apart with row-level security in Postgres.

How it got here: four rewrites
  1. Version 1: Node, Express, Prisma DeepSeek with tool calling, an admin panel and a CRM. Real shops used it.
  2. OMIX 2.0 I moved every action to the server. The model only wrote the text.
  3. ONNIX 3.0: TypeScript I took 14 days of real conversations (76 chats, 589 messages, 37 orders) and rebuilt the logic as one pure function. A test tries more than 10,000 combinations of inputs and runs in under a second.
  4. Current: Python and LangGraph Back to a tool-calling agent, but now each step of the sale limits what the model can do.

The code is private because it runs a business. I'm happy to walk through it on a call.

Pilot

A voice agent for incident calls

At my job on a Major Incident team, supervisors call when a tool fails for their team. We ask the same things every time: what failed, who is calling, which operation, how many people are affected. I built an agent that takes those calls in Colombian Spanish and leaves the report ready for the analyst.

Voice is harder than chat. People answer out of order, correct themselves, say "give me a second", or report a second failure in the middle of the call. Two things I learned the hard way: if a tool has a required field the caller hasn't mentioned yet, the model invents a value. And if a step speaks when it starts right after a question, the agent answers its own question. Now a field is saved only when the caller's own words back it up, and the code, not the model, decides what to ask next.

It runs on Pipecat: Deepgram turns speech into text, Silero VAD detects when the caller stops talking, Claude Haiku writes the answer, and a text-to-speech voice reads it, with a backup voice. Calls come in over WebRTC or Twilio.
