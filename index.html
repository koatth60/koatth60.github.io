Onix — WhatsApp AI sales agent (multi-tenant SaaS)

A sales assistant for shops on WhatsApp. It answers catalog questions, recognizes products from customer photos, recommends, takes the order, collects delivery data, shows an exact summary with confirm buttons and guides the payment. Each business has its own number, catalog, rules and personality, managed from a React panel with a built-in CRM.

  • LangGraph state machine with stage-scoped tools; illegal stage jumps are rejected in code.
  • Model routing per stage: DeepSeek for discovery, Gemini for checkout, Claude for vision and the premium tier — each with automatic fallback.
  • Photo → vision → embedding → pgvector top-3 product match, with keyword fallback.
  • Grounding check: if a reply quotes a price no tool returned, the model rewrites it.
  • Idempotent orders with checkout fingerprint and atomic stock decrement; Postgres row-level security per tenant.
  • Webhook signature check, message de-duplication, 2.5 s debounce per chat, human hand-off and owner approval of payment receipts.

Real-time voice agent for Major Incident reporting

A phone agent that replaces a human analyst on the Major Incident Management line of a large contact-center company. Supervisors call to report a technical failure; the agent runs the triage (is it a major incident?), takes the full report in natural Colombian Spanish, and leaves the ticket ready for the incident bridge. Built to survive people who go off-script: answers out of order, corrections, "give me a second", a second failure mid-call.

  • Streaming voice pipeline on Pipecat: WebRTC or Twilio → Deepgram STT with catalog key-terms → Silero VAD + smart-turn → Claude Haiku → TTS with fallback.
  • Two conversation engines compared on real calls: single agent with state block vs. a Pipecat Flows graph with small, stage-scoped tools.
  • Evidence-based extraction: a field is stored only if its verbatim quote exists in what the caller said — nothing invented, nothing misheard saved as fact.
  • Never asks twice: the next node is computed from data after every tool and every user turn.
  • Fuzzy catalog matching over 1,500 names in ~4 ms, keeping the prompt size constant so the prompt cache survives catalog edits.
  • Web admin panel to edit catalog, key-terms and agent settings without a redeploy. Strict mypy, ruff and pytest on every commit.

04 · How I work

Principles I learned shipping agents to real users.

01

The model drafts, the code decides

Facts, totals and state changes go through validated tools and database constraints. The LLM writes the words, not the truth.

02

Measure on real conversations

Every turn writes a trace: tools, model, tokens, latency. Redesigns start from production data, not from guesses.

03

Tests that run in a second

Decision logic is pure and tested without network, database or model calls — so it runs on every commit.

04

Own it end to end

From the schema to the Nginx config to the 2 a.m. fix. I've built platforms solo and kept them running for real users.
